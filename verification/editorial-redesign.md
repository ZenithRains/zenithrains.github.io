## 动态页与手机复查

用户随后指出动态归档内容贴住屏幕左侧。已复现：1280 px 视口下标题左缘为 316 px，列表左缘为 0。组件层的 `.updates-feed { margin: 0; }` 覆盖了同一元素上布局层 `.shell-narrow` 的自动居中边距。移除该冗余规则后，标题与列表左缘均为 316 px，列表宽度为 648 px。此前只检查页面溢出，遗漏了内容栏对齐，这项检查现已加入设计规范。

此次还改善了标题的均衡换行，允许人工标题词组在空间不足时内部换行，并按实际断点校正首页人像与封面的 `sizes`。320 px 内容视口下，人像实测约 112 px，单列封面约 192 px，图片声明与实际布局一致。

复查覆盖双语首页、研究列表、写作归档、动态归档、关于、简历、标签、Euler 文献、旅行图文集、证明札记、趋营养研究说明和 PDE 动态详情，共 24 条路由。每条路由检查实际 320、390、430 px 的页面视口，共 72 次测量：

- 页面宽度均等于实际视口宽度，无全页横向溢出。
- 各内容容器左右留白均为 20 px，标题和内容栏对齐。
- 公式内部的宽内容被自身滚动区域容纳，未推出页面边界。
- 中文首页与动态页完成补充截图观察，窄屏导航、姓名与人像、标题与正文仍可读。

测量记录保留在 [mobile-layout-metrics.json](mobile-layout-metrics.json)。本轮构建输出至 `/private/tmp/zenith-mobile-review`，Hugo 构建与 `git diff --check` 通过。

用户的第二张截图中，手机预览有明显的右侧空白。浏览器接口显示预览器标注 390 px 时，实际 `innerWidth` 和 `visualViewport.width` 为 300 px；设备像素比例约为 1.3，页面自身的 CSS `zoom` 为 1。重新加载与重置尺寸后仍可复现。实际页面标题与内容栏的左右留白均为 20 px。页面布局测量与预览截图的缩放显示存在不一致，右侧异常空白与该预览状态有关。当前接口不能独立控制预览器缩放，预览器的显示问题仍未修复。

为避免把标注尺寸当作真实页面尺寸，此次按浏览器读取的实际内容视口验收，设置预览尺寸为 416、507、559 px 时分别确认实际视口为 320、390、430 px。未通过网站 CSS 放大页面来补偿预览器。仍未完成常规手机浏览器、跨浏览器和 200% 文字缩放实测。
